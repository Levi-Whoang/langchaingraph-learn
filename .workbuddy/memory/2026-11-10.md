### 关键设计决策

1. **自建 `OfflineChatModel`（继承 BaseChatModel）作为无 key 兜底。**
   不联网，但返回真实 AIMessage / tool_calls / 支持 bind_tools 和 _stream。
   这样 agent 循环、中间件、流式全部能真实跑一遍，代码里不留 fake 分支。
   文件：`lc/offline_model.py`；工厂在 `lc/config.py` 的 `get_model()`。

2. **目录约定**：`lc/0X_概念.py` 单概念脚本，直接 `python lc/0X_xxx.py` 运行
   （脚本所在目录自动进 sys.path，所以 `from config import get_model` 可用）。
   文件名以数字开头**不能**当模块 import，只能直接运行 —— 这是有意为之。

3. **7 个章节 + config.py + offline_model.py + main.py 入口 + 学习笔记.md**。
   用户明确要求"每次对话总结到 md"，所以 `学习笔记.md` 是 append-only 的长期文件。

### 踩到的坑（已修，已写进笔记）

1. `BaseTool.args` 返回的是 JSON Schema 的 **properties 部分**，不含 `required`。
   要必填信息必须走 `tool.args_schema.model_json_schema()`。
2. `with_structured_output()` 内部 `bind_tools([PydanticClass])` —— 传的是**类本身**，
   不是工具实例。用 `getattr(t, "name")` 会炸，要用 `cls.__name__`。
3. 中文模糊匹配别用 2-gram：`calling` 里的 `in` 会误命中，一句提问搜出全部笔记。
   改成"英文词优先，中文 ≥3 字"。
4. `create_agent(response_format=...)` 在离线假模型下会死循环到 GraphRecursionError
   （假模型每次都返回 tool_call）。所以这个用法只写文档不实跑。
5. 中文注释里写英文双引号会 SyntaxError，文案统一用「」。
